- (decision) Replace the slide queue, cue track, slide anchors, speaker notes, and deck-bound scenario as the primary experience with a reusable capability-driven demo operator console.
- (decision) Primary information architecture is topology, resources, operations, and evidence; the two conference talks validate flows but do not define navigation.
- (decision) Use the fast path and mark unresolved interaction choices as assumptions rather than blocking UX drafting.
- (decision) The climax is stopping CoreBankAPI, submitting standard and instant payments, restarting CoreBankAPI, and seeing durable recovery and final assertions without leaving the console.
- (decision) DevProxy delay setup remains a manual external configuration operation; the console may expose status and supported on/off controls but does not edit checked-in proxy configuration.
- (assumption) Keyboard and mouse have full parity, with single-key shortcuts optimized for mid-sentence operation and mouse as the discoverable fallback.
- (assumption) The console may be projected deliberately, so its default view uses stage-readable summaries while raw evidence is available on demand.
- (assumption) The primary layout is one persistent cockpit with switchable workspaces, not a wizard, queue, or deep tree.
- (assumption) Payment operations default to editable presets; generated, supplied, and omitted idempotency modes are explicit, and resend-same-key is a first-class action.
- (assumption) Destructive resource actions require a short hold-to-confirm or typed confirmation shortcut and always keep the inverse recovery action in the same location.
- (assumption) Reset is exposed only for the disposable LoadTests topology through its existing supported reset workflow; the regular topology has no generic reset action.
- (event) Discovery captured from the operator-console brief, existing Story 7.4, ADR-015, instant-payment contracts, current scenario, README, and user corrections; fast-path distillation may begin.
- (event) Draft DESIGN.md and EXPERIENCE.md distilled; surface closure passed for topology, resource control, payments, evidence, load workflow, chaos, and both named talk journeys.
- (change) Corrected Journey A so topology health visibly degrades while CoreBank is stopped and returns healthy only after recovery; the console never claims health stayed green through an intentional outage.
- (decision) Use the supplied Docker Sandboxes screenshot only as composition inspiration: one near-black work surface, compact left navigation, strong verb/object hierarchy, muted command detail, simple top-bar controls, and a fixed lower action/detail region; do not copy its branding or exact styling.
- (decision) A fingerprint-verified attached AppHost permits allow-listed Aspire resource start/stop/restart commands after per-action confirmation; whole-AppHost stop remains forbidden because DemoRunner does not own that process.
- (decision) On relaunch, discard local UI/session history, re-read live Aspire and HTTP state, and start with empty operation history; never restore a prior passed state or cue checkpoint.
- (decision) Destructive actions use a modal with Cancel focused and one explicit confirmation key; keyboard hold and double-Enter confirmation are rejected.
- (change) Renamed the imported visual to operator-console-inspiration.png because it is a generic composition reference; do not attribute its exact appearance or branding to Docker Sandboxes.
- (event) DESIGN.md and EXPERIENCE.md finalized after three-lens validation; remaining documentation findings were resolved and the attached-resource authority was codified in amended ADR-015.
- (override) Overturns the 2026-09-03 decision that DevProxy fault setup stays a manual external operation. The console now owns fault injection as a first-class capability with operator-adjustable error, latency, and throttling levels.
- (decision) Fault levels apply live, mid-run. The console writes a session config and Dev Proxy's built-in file watcher reloads it without restarting the AppHost or the proxy resource.
- (decision) The console never writes the checked-in devproxy config files. It writes a gitignored generated session config; the checked-in files remain untouched and serve as the named default presets, preserving the LoadTests 9500-12000ms profile tuned to overrun the instant rail budget.
- (decision) Chaos controls are added to the existing DemoRunner console spines in Update mode, as a further capability of the same cockpit rather than a separate product.
- (decision) Fault controls get their own fifth workspace, reached by key 5, beside Operations/Resources/Evidence/Load Test. Sliders need vertical room and a fixed action region; placing them inside Resources would force the nested sub-navigation the IA bans.
- (decision) Fault controls are the second named exception to the global single-action-in-flight lock, joining the Burst control's Cancel. Raising latency or error rate while a burst or load run is in flight is the demonstration itself, so the lock must not block it.
- (decision) Fault levels use a stage-then-apply model: dragging a slider has no effect on the running system, and one explicit Apply commits every staged knob at once in a single config write. Staged-versus-live difference must be rendered truthfully.
- (decision) The LoadTests profile exposes all three knobs (error, latency, throttling), with its checked-in 9500-12000ms latency profile loaded as the named default preset. Adding error and throttling plugins to that profile changes what a load run means, so load-test assertions need review.
- (assumption) The console owns the Features:UseDevProxy gate when it starts an AppHost, since the gate is read at AppHost start. On an Attached topology the fault controls are visibly unavailable with the reason stated, matching how the spine already treats Attached.
- (decision) The Faults workspace ships spine-only, with no rendered mockup. It is built from the DESIGN.md component tokens and the EXPERIENCE.md behavioral rules alone.
